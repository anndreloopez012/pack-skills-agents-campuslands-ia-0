# Marco lógico

Ordena un proyecto público o social con la Metodología de Marco Lógico: del problema a la matriz
de cuatro filas y cuatro columnas que piden SEGEPLAN, la cooperación internacional y los fondos.

## Cuándo usarla

- «Tengo que presentar un perfil de proyecto y me piden marco lógico».
- «Haz el árbol de problemas de la desnutrición en mi municipio».
- «Revisa si mis indicadores y supuestos están bien».

## Qué necesito de ti

- El problema que quieres atender, dónde y a quién afecta.
- Datos que tengas (cifras, diagnósticos, quejas de la población) con su fuente.
- Quiénes participan o se ven afectados (involucrados).
- Duración y monto aproximado en quetzales (Q).
- Si falta algo importante, haz como máximo 3 preguntas cortas y sigue con supuestos marcados como
  «Supuesto:».

## Cómo trabajo

1. Análisis de involucrados: tabla con grupo, interés, problema percibido, recursos y postura.
2. Árbol de problemas: un solo problema central redactado como situación negativa (no como «falta
   de»), 3 a 5 causas directas con sus causas indirectas, y efectos directos e indirectos.
3. Árbol de objetivos: convierto cada problema en su situación positiva. Las causas pasan a ser
   medios; los efectos, fines.
4. Análisis de alternativas: agrupo medios en 2 o 3 estrategias y las comparo por costo, tiempo,
   capacidad institucional e impacto. Recomiendo una y digo por qué.
5. Matriz: Fin (al que contribuye), Propósito (uno solo, el cambio en la población), Componentes
   (productos que entrega el proyecto) y Actividades (con presupuesto).
6. Indicadores con fórmula, unidad, línea base, meta y plazo. Medios de verificación concretos
   (documento, quién lo emite, cada cuánto). Supuestos: condiciones externas fuera del control del
   proyecto, redactadas en positivo.
7. Reviso la lógica vertical (si se hacen las actividades y se cumplen los supuestos, se logran los
   componentes, y así hacia arriba) y la horizontal (cada fila se puede medir y verificar).
8. Si sirve, dibujo los árboles con `diagram-design`.

## Lo que te entrego

```
1. Involucrados
| Grupo | Interés | Problema percibido | Recursos o mandato | Postura |

2. Árbol de problemas (texto con niveles) y árbol de objetivos

3. Alternativas
| Alternativa | Costo (Q) | Plazo | Capacidad | Impacto | Elegida |

4. Matriz de marco lógico
| Nivel | Resumen narrativo | Indicador (fórmula, línea base, meta) | Medio de verificación | Supuestos |
| Fin | | | | |
| Propósito | | | | |
| Componente 1 | | | | |
| Actividad 1.1 | | Presupuesto: Q | | |

5. Revisión de lógica vertical y horizontal (qué falla y cómo corregirlo)
```

## Reglas

- Un solo propósito por proyecto. Si salen dos, son dos proyectos.
- El problema nunca se redacta como «falta de» la solución («falta de escuela» esconde el problema
  real: niños sin acceso a educación).
- Los supuestos no pueden ser cosas que el proyecto sí controla ni condiciones fatales; si un
  supuesto es muy improbable, el proyecto no es viable y lo digo.
- Todo indicador sigue el criterio SMART y tiene un medio de verificación real; nada de «informe
  del proyecto» sin decir quién lo emite.
- No inventes líneas base: marca «Pendiente: línea base» y propone la fuente (INE, MSPAS, MINEDUC,
  registros municipales). Para buscarla usa `source-researcher`.
- Formatos de SEGEPLAN o del cooperante: verificar el vigente; revisado: noviembre de 2026.
- Si el diagnóstico tiene datos de personas, propone `data-shield` antes de trabajarlo.

## Ejemplo

**Pedido:** «Proyecto para reducir enfermedades diarreicas en niños de una aldea».
**Entrega (resumen):** problema central «Alta incidencia de enfermedades diarreicas en menores de
5 años»; causas: agua no segura, malas prácticas de higiene, letrinas en mal estado; propósito
«Disminuida la incidencia en menores de 5 años de la aldea»; componentes: sistema de cloración,
familias capacitadas en higiene, letrinas mejoradas; indicador del propósito con línea base del
puesto de salud (pendiente) y supuesto «El puesto de salud mantiene su registro mensual».
